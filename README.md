# Meeplio

Meeplio — русскоязычный Telegram-бот, который помогает выбрать настольную игру для конкретной компании и вечера.

Пользователь отвечает на несколько коротких вопросов: сколько человек будет играть, сколько есть времени, какой нужен уровень сложности, какое настроение и насколько уместно соревнование. Бот предлагает три подходящих игры, объясняет выбор и предупреждает, кому вариант может не подойти.

> «Нас будет четверо, у нас около часа, и мы не хотим сложных правил. Во что сыграть?»

## Зачем это нужно

Каталоги настольных игр дают много фильтров, но не отвечают на простой вопрос: «Во что нам сыграть сегодня?». Meeplio должен дать понятный ответ за 2–3 минуты, без необходимости разбираться в названиях, жанрах и механиках игр.

Проект ориентирован прежде всего на русскоязычных игроков, которые выбирают игру дома с друзьями, семьёй или партнёром и не хотят ошибиться с выбором.

## Как будет работать подбор

1. Пользователь запускает `/pick`.
2. Бот задаёт до восьми вопросов через inline-кнопки.
3. Ответы и прогресс сохраняются, поэтому сценарий можно продолжить после паузы.
4. Алгоритм отбрасывает неподходящие игры по жёстким ограничениям: числу игроков, возрасту, времени, типу взаимодействия и допустимому конфликту.
5. Оставшиеся игры получают оценку по настроению, сложности, времени, опыту компании и другим параметрам.
6. Бот показывает три разных варианта: лучшее совпадение, более простой вариант и необычную альтернативу.

Если точных совпадений мало, бот объяснит, какое ограничение сузило выбор, и предложит изменить один параметр. Игры с неподходящим количеством игроков не попадут в рекомендации.

## Планируемые возможности MVP

- команды `/start`, `/pick`, `/saved`, `/feedback`, `/help` и `/cancel`;
- последовательный опрос с кнопками «Назад», «Отменить» и «Начать заново»;
- каталог вручную размеченных настольных игр;
- детерминированный алгоритм рекомендаций без LLM;
- карточки игр с причинами рекомендации и предупреждениями;
- избранное и оценка рекомендаций;
- сохранение сессий, обратной связи и продуктовой аналитики;
- обработка ошибок и пустых результатов.

## Технологии

Планируемый стек:

- TypeScript и Node.js;
- grammY и Telegram Bot API;
- Cloudflare Workers и Wrangler;
- Supabase и PostgreSQL;
- Zod для валидации;
- ESLint, Prettier и Vitest;
- GitHub Actions для CI/CD.

## Начало работы

Требуется Node.js 22 или новее.

```bash
npm install
cp .env.example .env
# Укажите BOT_TOKEN, SUPABASE_URL и SUPABASE_KEY в переменных окружения shell
BOT_TOKEN=<token> SUPABASE_URL=<url> SUPABASE_KEY=<key> npm run dev
```

| Команда          | Назначение                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run dev`    | Запускает бота в polling-режиме с перезапуском при изменениях.                                                                                                 |
| `npm run build`  | Компилирует TypeScript в `dist/`.                                                                                                                              |
| `npm test`       | Запускает unit-тесты.                                                                                                                                          |
| `npm run lint`   | Проверяет код ESLint.                                                                                                                                          |
| `npm run format` | Форматирует исходники через Prettier.                                                                                                                          |
| `npm run import` | Импортирует `data/seed-catalog.json` в Supabase. Для другого CSV/JSON-файла: `npm run import -- путь/к/каталогу.csv`. Требует `SUPABASE_URL` и `SUPABASE_KEY`. |

На этом этапе бот отвечает на `/start`, `/help` и `/health`.

## CI/CD и деплой

`CI` запускает lint, тесты и build для каждого pull request и при push в `main`.
После успешного CI для push в `main` workflow `Deploy` подключается к VPS по SSH,
обновляет `/opt/meeplio`, устанавливает зависимости, собирает проект и перезапускает
PM2-процесс `meeplio`.

Перед первым деплоем создайте GitHub Actions secrets (значения не хранятся в репозитории):

- `DEPLOY_SSH_KEY` — приватный SSH-ключ с доступом пользователя `root` к VPS;
- `DEPLOY_SSH_FINGERPRINT` — SHA256 fingerprint SSH host key VPS;
- `DEPLOY_REPO_SSH_KEY` — private half read-only GitHub deploy key для клонирования репозитория;
- `DEPLOY_HOST` — `89.223.66.116`;
- `DEPLOY_USER` — `root`;
- `BOT_TOKEN` — токен Telegram-бота;
- `SUPABASE_URL`;
- `SUPABASE_SERVICE_KEY` — service key, передаваемый приложению как `SUPABASE_KEY`.

На VPS должны быть установлены Node.js 22+, npm, Git и PM2. Репозиторий должен быть
доступен серверу по HTTPS для первоначального `git clone`.
